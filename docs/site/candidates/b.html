カメラ

カメラが、むやみに動かない。

クリックのたびに寄っては戻る動画は、見ていて落ち着きません。Launchloomは一度決めた画角をそのまま保ち、次の操作が十分に離れた場所で起きたときだけカメラを動かします。動かすときの軌道はなめらかにつながっているので、切り替わりで画面が跳ねることもありません。

一度の入力から

公開に必要なものが、そろって出てくる。

画面のモックではありません。再生できるMP4、そのまま置けるHTML、そのまま投稿できる文章、そして全ファイルのSHA-256を記録したマニフェストが出てきます。

01

実物を映した紹介映像

1280×720、H.264。自分のプロダクトを実際に操作した収録から組み立てます。ダミー画面でも、ストック映像でもありません。

02

組み直した縦長版

720×1280は専用のレイアウトで組み直します。横長を真ん中で切り抜いただけ、にはしません。

03

ランディングページ

映像を埋め込んだHTML・CSS・JSが一式で出ます。CDNもビルドもフレームワークも使っていないので、どこに置いても動きます。

04

手を入れられる投稿文

X、LinkedIn、Threads、Bluesky、YouTube、Instagram、TikTokそれぞれの体裁で。UTM付きのリンクと、文字数の検査つきです。

05

字幕とポスター

画面に出る見出しをSRTにしたもの（音声の書き起こしではありません）。横長・縦長それぞれのサムネイル用静止画も付きます。

06

そのまま渡せる一式

全部をまとめたZIPと、素材の出どころを記録したマニフェスト。社外に出せない根拠メモと生の収録は、意図的に入れていません。

音声つき

ナレーション付きの、28秒版。

同じ企画・同じ工程に、ナレーションと音楽を重ねたものです。横長と縦長を一度の書き出しで作ります。音を出して再生してみてください。

音楽はこちらで用意した既存の音源です。生成した音は使っていません。Launchloomはそれをナレーションの下に敷き、全体の音量を一度だけそろえて、映像の長さに合わせて切ります。

機能の根拠として書いた社外秘のメモと、生の画面収録は、意図的に入っていません。 manifest.json にその旨が書かれ、書き出しのたびに検査されます。

何をどこまで検証したか →

自分の道具で、自分を撮る

上の映像が、その結果です。

スタジオを一通り操作するところを収録し、その収録をLaunchloomに読み込ませて、自分自身の紹介映像を作らせました。その過程で、実際のバグが2つ見つかりました。自分の道具を自分で使う意味は、そこにあります。

日本語の行頭に「、」「。」が来ていた。日本語で書き出した映像はどれも、この道具は自分が扱っている言語を分かっていない、と言っているようなものでした。いまは禁則処理を入れてあります。MP4 が MP と 4 に割れることもなくなりました。

縦長が、いちばん見せたい画面を潰していた。16:10のデスクトップ収録を正方形に近い枠へ押し込んでいたため、見せたい画面が読めなくなっていました。いまは収録そのものの比率を保ったまま、ほぼ全幅で見せます。

縦長は、切り抜きではなく別の映像です。

見出し、画面を見せる枠、キャプションを、9:16用に配置し直します。元にする構成は横長と同じなので、両者で言っていることがずれることはありません。

書き出す前に

読んでから、書き出す。

収録が終わった時点で、制作はいったん止まります。まだ映像は書き出されていませんし、生成AIにも何も送っていません。実際に収録された画面の1コマと、これから使われる文言をすべて確認し、直したうえで承認します。

直しても、構造は壊れない

各シーンの役割と、どの承認済み機能を指しているかは固定されています。言い回しを直しても、別の主張にすり替わることはありません。直した箇所は operator-edited として記録されます。

1行だけ直す

一度仕上げたキャンペーンは、手元の素材のまま作り直せます。CTAの言い回しを変えて、15秒ほどで書き出し直し。録り直しも、生成AIへの再依頼も起きません。

はっきりさせておきたいこと

Launchloomがやらないこと。

この手のツールは、見栄えのするものなら喜んで作ってしまいます。Launchloomは逆で、誰も確かめていないことを言わないように作ってあります。

✕

機能をでっち上げる

映像に出てくる主張は、すべてあなたが書いた企画から来ます。ひとつずつに根拠メモが付きます。生成した映像は、そうと明記した冒頭のイメージ部分だけで、機能が存在する証拠にはなりません。

✕

勝手に投稿する

実際の投稿は既定で無効です。キャンペーンを公開できる状態にするのは、作り終えることとは別の判断です。投稿ごとに、その文面・メディア・アカウント・日時に結び付いた承認が要ります。

✕

「送れた」を「出た」と言い張る

投稿が本当に存在するかどうかは、Postizから読み直して確かめます。送信がタイムアウトしたらそう表示し、やみくもに再送はしません。実際に何が存在するかを見せたうえで、判断はあなたに委ねます。タイムアウトは、出た証拠にも出ていない証拠にもならないからです。

✕

エンゲージメントを稼ぐ

一括返信も、DMも、買った反応も、アカウントの量産もありません。実装していませんし、する予定もありません。追加するプルリクエストはお断りします。

✕

持っていない数字を埋める

取得できない指標は、取得できないままにします。イベント数は人数ではありませんし、判断できるだけのデータがないときは、ないと表示します。

3分

クローンして、動かしてみる。

アカウントもAPIキーも登録も要りません。サンプルは、リポジトリに同梱した小さなタスク管理アプリを実際に操作して収録し、キット一式を書き出します。

必要なのは Python 3.11以降、FFmpeg、Chromium の3つだけです。macOSとDockerは実機で確認しています。どこまで確かめたかは、検証記録に分けて書いてあります。

ソースを読む 実際に検証した範囲 
git clone https://github.com/FORIFOR/Launchloom.git
cd Launchloom
python3 -m venv .venv && source .venv/bin/activate
python -m pip install -e .
python -m playwright install chromium
# FFmpeg・ブラウザ・フォントを先に確かめる
python -m launchloom doctor
python -m launchloom serve

お願いしたいこと

まだ、私のMac1台でしか動かしていません。

あとはLinuxコンテナ（amd64とarm64）とCIだけです。Windowsでは一度も起動していません。実際のSNSアカウントに投稿したこともありません。どちらも、私の手元だけでは確かめようがありません。ほかの環境で動かした報告が1つ届くほうが、私がもう1週間コードを書き続けるより価値があります。

  • 20秒で終わります。 selftest は一時ディレクトリの中で実際にキットを作り、出来たものを検査します。アカウントもAPIキーもネットワークも不要で、ほかの場所には一切触れません。
  • 貼るのは1ファイルだけ。 launchloom-selftest.txt が書き出されます。それを貼れば報告は完了です。状況をご自身で説明していただく必要はありません。
  • うまくいかなかった報告のほうが助かります。 これまで直した不具合のうち10件は、テストでは見つからず、実際に動かした瞬間に分かったものでした。
お願いの全文を読む TESTING.md

何もインストールしたくなくて、Dockerもない場合はCodespaceで開く方法もあります。環境が自動で用意され、実行するコマンドが表示されます。

# すでにクローン済みなら
python -m launchloom selftest

# 何もインストールしたくない場合 —
# イメージは amd64 と arm64 の両方に対応
docker run --rm -e CHROMIUM_NO_SANDBOX=1 \
  ghcr.io/forifor/launchloom \
  python -m launchloom selftest
